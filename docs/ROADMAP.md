# Дорожная карта и критерии (по ТЗ §10, §11)

Каждый шаг закрыт только после прохождения автоматических и экранных проверок.
Незакрытое названо здесь явно.

## Шаг 1 — Основа и тестовые данные — СДЕЛАНО

Критерии (фальсифицируемые — рядом названа правка, которая их сломает):

- [x] **Репозиторий, модели, миграции.** Все сущности §9 заведены; `manage.py
  makemigrations` не предлагает изменений. Ломается: удалить поле из модели без
  миграции — проверка миграций это покажет.
- [x] **Тестовые данные.** `seed_demo`: 10 VIN, 2 ИНН, 2 менеджера, админ,
  назначения и закрепления. Идемпотентна. Ломается: повторный запуск не плодит
  дубли (get_or_create).
- [x] **Создание ТС и назначений.** Через админку и через seed. Ограничение
  «одно действующее назначение на ТС» — на уровне БД (UniqueConstraint с
  условием `ended_at IS NULL`). Ломается: попытка создать второе активное
  назначение падает на IntegrityError.
- [x] **Вход по активной паре ИНН+VIN.** Проверяется именно пара, а не отдельное
  существование. Ломается: пара «ИНН арендатора B + VIN арендатора A» должна
  получить отказ — живой прогон сценарий A подтверждает.
- [x] **Изоляция доступа проверена первой.** `vehicles_for_staff`,
  `can_staff_access_vehicle`; менеджеры 1 и 2 не пересекаются; посторонний не
  видит ничего; водитель заперт на один VIN и теряет доступ при закрытии
  назначения. Ломается: закрыть назначение → `can_staff_access_vehicle` даёт
  False (тест `test_closing_assignment_drops_manager_visibility`).

Автоматические проверки: 29 тестов зелёные (расчёт ТО, права, вход, валидаторы).
Живой прогон сервера: вход, кабинет, изоляция — сырой вывод в README.

## Шаг 2 — Отчёт водителя — СДЕЛАНО (кроме проверки на телефонах)

Критерии (фальсифицируемые):

- [x] **Четыре экрана (§5).** Экран 1 (фото одометра, показание, блок ТО),
  экран 2 (4 обязательных ракурса + до 5 дефектов), экран 3 (замечания,
  комментарий, краткая проверка), экран 4 (подтверждение с номером). Ломается:
  отправка без одного из четырёх ракурсов → экран 3 перечисляет недостающее и
  не отправляет (`test_cannot_submit_without_required_photos`).
- [x] **Черновик на сервере, один на назначение.** Поля экранов хранятся в
  `Report` (state=draft), «Назад»/«Далее» их не теряют. Ограничение
  `unique_draft_per_assignment` на уровне БД.
- [x] **Фото в закрытое хранилище.** Проверка реального формата (магические
  байты), приведение к JPEG, поворот по EXIF и сброс метаданных (включая
  геолокацию), миниатюра, цель ≤2 МБ, до 15 МБ на исходник. Структура §9
  подтверждена на диске: `vehicles/000001_VIN/reports/2026-10/report_1/...`.
- [x] **Безопасная повторная отправка.** Черновик переходит в «отправлен» той же
  строкой; повторная отправка возвращает тот же отчёт. Ломается: двойной
  `submit_report` даёт один отчёт и одно показание
  (`test_submit_idempotent_no_duplicate`).
- [x] **Передача ТО, подтверждает сотрудник.** «ТО выполнено» создаёт запись
  `Maintenance` со статусом «на проверке»; без документа отправка возможна, но
  подтверждённым ТО автоматически не становится. Просрочка отправку не блокирует.
- [x] **Закрытая раздача вложений.** Файл чужого VIN по прямой ссылке →
  404 (`test_foreign_attachment_not_served`).

**Недоказано на стенде:** реальные телефоны Chrome Android / Safari iPhone —
это ручная экранная проверка, требует устройств; декодирование HEIC
(`pillow-heif` установлен, но на входе были только JPEG); полный офлайн-режим в
первый этап по ТЗ не входит.

## Шаг 3 — Кабинет сотрудников — СДЕЛАНО (кроме экранной проверки на телефонах)

Критерии (фальсифицируемые — рядом названа правка, которая их сломает):

- [x] **Срез завершённого месяца на конец месяца, без пересчёта по сегодня.**
  Состояние ТО и пробег берутся по показаниям и ТО с датой не позже среза
  (`asof.accepted_reading_asof`, `asof.confirmed_maint_asof`). Ломается: показание
  180 000 км от 05.10 не должно влиять на сентябрьский дашборд — пробег остаётся
  170 000 (`test_as_of_mileage_not_recomputed_by_today`,
  `test_asof_ignores_maintenance_after_cut`).
- [x] **Показатели §7.** Всего VIN в парке, передали сведения (+доля), передали
  фото ТС, не передали, ТО просрочено/требуется/нет базы, ТС без актуального
  пробега. Живой прогон демо: 10 / 1 (10 %) / 1 / 9 / 1 / 1 / 6 / 6. Ломается:
  убрать отчёт у VIN → «передали сведения» падает на 1, «не передали» растёт.
- [x] **Сравнение с прошлым месяцем.** Числовая разница и доля каждого месяца;
  при нулевой базе прошлого месяца процент изменения не считается; для неполного
  текущего — «Месяц не завершён» (`metrics.compare_months`). Ломается:
  `test_zero_prior_base_no_percent`, `test_incomplete_current_month_note`.
- [x] **Таблица контроля с фильтрами.** Все колонки §7; фильтры: нет отчёта,
  просрочено/требуется/нет базы, показания на проверке, ТО на проверке, поиск
  VIN/ИНН. Ломается: `test_filters` (флаг `no_report` при наличии отчёта даёт
  пустой список).
- [x] **Карточка VIN.** Общие данные, действующее назначение, история назначений,
  отчёты с фото и комментариями, история показаний и ТО, журнал исправлений,
  скачивание ZIP. Чужой VIN прямым запросом → 404
  (`test_manager_cannot_open_foreign_card`, живой прогон: menedжер видит своё 200,
  чужое 404, в парке 5 ТС).
- [x] **Проверка спорных показаний и ТО.** Принять/отклонить/исправить показание
  и подтвердить/отклонить ТО с обязательной причиной при исправлении; исходное
  значение сохраняется в журнале аудита; отклонение ТО прежнюю базу не меняет
  (`test_correct_preserves_original_in_audit`,
  `test_reject_maintenance_keeps_prior_base`). Живой прогон: исправление
  155 000 → 156 000 км записано в журнал с причиной и автором.
- [x] **Экспорт.** Отфильтрованная таблица в .xlsx (теми же значениями, что на
  экране) и выбранный отчёт с вложениями одним ZIP (`exports`). Ломается:
  `test_xlsx_is_zip_container`, `test_report_zip_has_manifest`.
- [x] **Область видимости.** Дашборд, таблица, карточка, экспорт и действия — все
  через `vehicles_for_staff`/`can_staff_access_vehicle`; posторонний сотрудник не
  видит ничего, менеджер — только свой парк (`test_manager_scope`,
  `test_dashboard_requires_login`).

Автоматические проверки: 72 теста зелёные (24 новых на §7). Живой прогон сервера:
вход администратора/менеджера, дашборд, таблица, карточка, экспорт, изоляция,
исправление с аудитом — сырой вывод в README.

**Недоказано на стенде:** экранная проверка таблицы и карточки на реальных
телефонах; история показателей «по менеджеру на дату события» реализована через
`Report.manager_at_report`, но разрез дашборда по менеджеру использует ТЕКУЩЕЕ
закрепление (ТЗ §7: «рабочая очередь — к текущему») — согласовать с заказчиком,
нужен ли отдельно исторический разрез по менеджеру прошлых месяцев.

## Шаг 4 — Импорт и запуск — ЧАСТИЧНО (оба импорта сделаны; запуск и эксплуатация — нет)

### GPS-импорт из Excel (§8) — СДЕЛАНО

Критерии (фальсифицируемые):

- [x] **Чтение формата.** .xlsx, первый лист, заголовки в первой строке, до
  10 000 строк и 10 МБ; шаблон для скачивания; сопоставление колонок VIN/пробег/
  дата с сохранением; старый .xls отклоняется с подсказкой пересохранить.
  Формулы не выполняются — ячейка «=…» это ошибка (`normalize_mileage`,
  `test_mileage_bad`).
- [x] **Нормализация значений.** Пробелы в числах (в т.ч. неразрывные), дробное
  вниз с отметкой, отрицательное/нечисловое/пустое → ошибка; дата
  datetime/«ГГГГ-ММ-ДД»/«ДД.ММ.ГГГГ», будущая → ошибка; нет колонки даты → общая
  дата выгрузки (`normalize_date`, `test_date_variants_and_future`,
  `test_common_date_when_no_column`).
- [x] **Категории строк §8.** Готово / требует проверки / уже существует / ошибка.
  Полный дубль VIN+дата+пробег+источник пропускается; разные показания VIN на одну
  дату — конфликт на проверку (`classify_import_row`, `test_*` в `GpsClassifyTests`).
- [x] **Предпросмотр не меняет данные; применение атомарно.** Партия хранит
  исходный файл, автора, дату, итог; при ошибке откат целиком (транзакция).
- [x] **Критерий приёмки §11 «GPS импорт».** Корректная строка добавлена,
  неизвестный VIN в ошибках (Excel ошибок с номером строки и причиной), конфликт
  на проверке, повторный файл без дублей, отчёт водителя не засчитан
  (`GpsImportIntegrationTests`). Живой прогон: предпросмотр 3/1/1/0/1, применение,
  повторная загрузка 0 готово / 2 дубля, Excel ошибок строка 4 «неизвестный VIN».
- [x] **Отмена партии администратором с причиной.** Записи исключаются из расчёта
  (`Vehicle.accepted_reading_rows` отбрасывает отменённые партии), но остаются в
  истории; актуальный пробег и ТО пересчитываются. Ломается:
  `test_revert_excludes_from_calc`. Живой прогон: после отката VIN без принятых в
  расчёте, обе записи целы в истории.
- [x] **Импорт не создаёт фото, не подтверждает ТО, не отмечает отчёт.** Показания
  водителя и GPS — разные записи, друг друга не перезаписывают
  (`test_apply_writes_and_does_not_count_report`).

Автоматические проверки: 87 тестов зелёные (15 новых на §8). Живой прогон импорта,
отката и аудита — сырой вывод в README.

### Массовое подключение парка (§7) — СДЕЛАНО

Критерии (фальсифицируемые):

- [x] **Формат §7.** VIN, ИНН, менеджер, госномер, модель, пробег и дата
  показания, дата и пробег ТО — девять колонок одним файлом; .xlsx, первый лист,
  заголовки в первой строке, до 10 000 строк и 10 МБ, формулы не выполняются.
  Обязательны VIN/ИНН/менеджер; остальные — по желанию.
- [x] **Необязательные пары.** «Пробег + дата показания» и «дата + пробег ТО» —
  обе ячейки пустые — пары нет (валидно), заполнена только одна — ошибка. Те же
  правила разбора чисел и дат, что у GPS-импорта (пробелы, дробное вниз, запрет
  будущих дат) — переиспользованы из `gpsimport`, не продублированы. Ломается:
  `test_pair_half_filled_is_error`.
- [x] **Категории строк.** READY (создаст/переоткроет ТС) / EXISTS (уже
  подключено ЭТОМУ арендатору — пропуск) / CONFLICT (закреплено за ДРУГИМ —
  массовый импорт не разрывает действующее назначение) / ERROR (формат,
  неизвестный менеджер, неполная пара, пробег ТО больше показания, VIN повторяется
  в файле). Ломается: `test_classify_conflict_other_tenant`,
  `test_existing_other_tenant_is_conflict_and_untouched` (чужое назначение после
  импорта цело).
- [x] **Применение создаёт весь куст сущностей одной READY-строкой.** ТС (если
  новый), арендатор (get_or_create по ИНН), назначение, закрепление менеджера,
  и, если указаны, начальное показание (`source=manual`, сразу `accepted`) и
  начальное ТО (`status=confirmed`, `basis=initial` — как в демо-данных).
  Ломается: `test_new_vehicle_creates_everything`.
- [x] **Существующее не трогается молча.** EXISTS и CONFLICT не создают и не
  меняют ничего — идентификационные поля (госномер/модель) уже существующего ТС
  бульк-импорт не перезаписывает (осознанное решение: исправление — через
  карточку ТС с причиной, не тихим повторным импортом).
- [x] **Доступ и аудит.** Только администратор (§1: «Администратор подключает
  парк и сотрудников»); менеджер получает 404. Партия (`ImportBatch.kind=fleet`)
  хранит файл, автора, итог; откат для этого типа партии осознанно заблокирован
  (создание ТС/назначений откатывать как GPS-показания нельзя — это были бы
  реальные сущности, не переключение видимости) и отказывает вежливо, не падая.
  Ломается: `test_revert_blocked_for_fleet_batch`.

Автоматические проверки: 108 тестов зелёные (21 новый). Живой прогон: шаблон,
предпросмотр 4 строк (1 ready / 1 exists / 1 conflict / 1 error), применение,
партии с типом «парк», Excel ошибок с колонкой «Поле», блокировка отката,
изоляция менеджера — сырой вывод в README.

### Резервное копирование и восстановление (§10) — СДЕЛАНО на локальном стенде

Критерии (фальсифицируемые — рядом названа правка, которая их сломает):

- [x] **Копия атомарна и независима от конкурентной записи.** `scripts/backup.sh`
  снимает БД через `sqlite3 .backup` (безопасная онлайн-копия, не голый `cp`
  файла, который может попасть на середину записи) и архивирует
  `PRIVATE_MEDIA_ROOT` в `.tar.gz` с фиксированным именем верхнего каталога
  (через симлинк — восстановление не зависит от реального пути на сервере).
  Пишет во временный каталог и переименовывает в итоговый только после того, как
  все шаги прошли без ошибки — недописанная копия не попадёт под ротацию.
- [x] **Манифест — независимая точка сверки, снятая ДО копирования.**
  `manage.py backup_manifest` считает строки по ключевым таблицам живым
  запросом к БД и пишет JSON первым шагом. Решение: сверять восстановленное НЕ с
  самим дампом (он согласится с любой своей ошибкой), а с этим внешним снимком.
- [x] **Ротация хранит `BACKUP_KEEP_DAYS` копий (по умолчанию 30).** Сортировка
  по имени совпадает с хронологией (имя — метка времени). Живой прогон: из 33
  копий после очередного `backup.sh` осталось 30, удалены три самые старые,
  свежая настоящая копия — среди оставшихся.
- [x] **Восстановление — на тестовый стенд, не поверх рабочих данных.**
  `scripts/restore.sh` пишет только в `RESTORE_DIR` (по умолчанию
  `./restore_test`, в `.gitignore`); рабочие `db.sqlite3`/`private_media` не
  трогает. PostgreSQL-путь: дамп снимается (`pg_dump -Fc`), но автоматическое
  восстановление в тестовую БД на этом стенде не настроено (нет согласованного
  сервера) — скрипт честно печатает это и останавливается, не притворяясь.
- [x] **Проверка обязана уметь упасть — проверено разрывом, не на словах.**
  `manage.py verify_restore` сверяет счётчики девяти таблиц с манифестом и
  существование файла на диске для каждого `Attachment.stored_path`. Живой
  прогон с намеренной порчей: (1) удалена строка `Attachment` в восстановленной
  копии → `MISMATCH attachment: восстановлено 4, манифест 5`, код выхода 1; (2)
  целая БД, но удалён файл вложения на диске → `MISMATCH файлы вложений: 4/5`,
  код выхода 1. Обе слепые зоны (строка без файла, файл без строки) ловятся
  независимо друг от друга — ни то, ни другое не замаскировано другим.
  Чистое восстановление без порчи: все девять таблиц и файлы — `OK`, код
  выхода 0.

**Недоказано на стенде:** восстановление PostgreSQL (нет согласованного
сервера — только sqlite-путь прогнан живьём); цель «потеря не более суток,
восстановление до одного рабочего дня» — организационная договорённость о
периодичности запуска `backup.sh` (например, через cron), сам факт срабатывания
по расписанию здесь не настраивался.

### Запуск и эксплуатация, остальное (§10) — НЕ НАЧАТ

Домен, HTTPS (`DJANGO_SECURE_SSL` готов в настройках), журналы ошибок, пилот на
10–15 ТС за полный цикл отчётности. Требует согласованного сервера в России — на
локальном стенде не доказуемо.

## Нефункциональные (§10) — НЕ ИЗМЕРЕНО

Нагрузка (2000 ТС, 150 сотрудников, 50 сессий), время страниц (<3 с), импорт
10 000 строк (<60 с), ежедневные копии и восстановление. Измерять вторым прибором
на согласованном сервере; сейчас стенда с такой нагрузкой нет.

## Открытые вопросы к заказчику (§4, §11)

- Правила доступа, хранения и текст уведомления для водителя (ИНН + реальные
  документы → проект не анонимный).
- Подтверждение значений: 4 ракурса, месячная периодичность, пороги
  5 000 / 1 000 / 3 000 км, срок хранения отправленных отчётов, перечень менеджеров.
- Реальная обезличенная выгрузка GPS и исходный список VIN/ИНН для настройки импорта.
